Como reproduzir o relatório

Do download dos boletins de urna do TSE até a publicação no GitHub Pages.

1Requisitos

  • Python 3.10 ou superior.
  • ~45 GB livres em disco: os CSVs descompactados do 1º turno somam ~35 GB (São Paulo sozinho tem 8 GB), os do 2º turno ~1 GB, mais os ZIPs e ~1 GB de cache Parquet.
  • 16 GB de RAM recomendados. O DuckDB processa em streaming e usa disco temporário se faltar memória.
python3 -m pip install duckdb pandas jupyter nbconvert

2Baixar os dados do TSE

Os arquivos estão no Portal de Dados Abertos do TSE — Resultados 2026. Procure o recurso “Boletim de urna” (BU na web). Há um ZIP por UF e por turno, mais o ZZ (exterior):

TurnoPadrão do nomeExemplo
1ºbweb_1t_<UF>_<DDMMAAAAHHMM>.zipbweb_1t_AC_051020261403.zip
2ºbweb_2t_<UF>_<DDMMAAAAHHMM>.zipbweb_2t_AC_261020260742.zip

O sufixo é a data e hora em que o TSE gerou o arquivo. Se o TSE republicar os dados, ele muda — confira no portal antes de baixar. Os links seguem o padrão do CDN do TSE; o script abaixo baixa as 28 UFs de cada turno:

#!/usr/bin/env bash
# baixar_dados.sh — ajuste T1 e T2 conforme os nomes listados no portal
set -euo pipefail
BASE_URL="https://cdn.tse.jus.br/estatistica/sead/eleicoes/eleicoes2026/buweb"
T1="051020261403"   # carimbo do 1º turno
T2="261020260742"   # carimbo do 2º turno
UFS="AC AL AM AP BA CE DF ES GO MA MG MS MT PA PB PE PI PR RJ RN RO RR RS SC SE SP TO ZZ"

mkdir -p 1o-turno 2o-turno
for uf in $UFS; do
  curl -fL --retry 3 -o "1o-turno/bweb_1t_${uf}_${T1}.zip" "$BASE_URL/bweb_1t_${uf}_${T1}.zip"
  curl -fL --retry 3 -o "2o-turno/bweb_2t_${uf}_${T2}.zip" "$BASE_URL/bweb_2t_${uf}_${T2}.zip"
done

Se algum link der erro 404, copie o endereço direto da página do portal (botão “Baixar” de cada recurso): o TSE às vezes muda o caminho do CDN entre publicações.

3Descompactar

Cada ZIP contém o CSV da UF e o leiame em PDF, que descreve todas as colunas.

for z in 1o-turno/*.zip; do unzip -o "$z" -d 1o-turno; done
for z in 2o-turno/*.zip; do unzip -o "$z" -d 2o-turno; done

A estrutura final deve ficar assim:

urnas/
├── 1o-turno/              # bweb_1t_*.csv  (28 arquivos)
├── 2o-turno/              # bweb_2t_*.csv  (28 arquivos)
├── analise_urnas.ipynb    # notebook de análise
├── gerar_relatorio.py     # gera docs/index.html
├── relatorio_template.html
└── docs/                  # site publicado no GitHub Pages
    ├── index.html
    └── como-executar.html

4Executar o notebook

Na primeira execução, o notebook lê todos os CSVs (codificação Latin-1, separador ;) e grava o cache em cache/. Em um Mac com 8 núcleos isso levou cerca de 3 minutos. As execuções seguintes reutilizam o cache e terminam em segundos.

jupyter nbconvert --to notebook --execute --inplace analise_urnas.ipynb

Ou abra de forma interativa com jupyter lab analise_urnas.ipynb. O notebook produz:

  • resultado do 1º e 2º turnos (Presidente, Governador, Senador, Deputados);
  • urnas com votos para um único candidato;
  • variação do comparecimento por urna e por cidade entre os turnos, destacando as acima de 10%;
  • testes estatísticos de indícios de manipulação;
  • CSVs em resultados/.

Parâmetros na primeira célula de código:

VariávelPadrãoEfeito
LIMIAR_VARIACAO0.10limite de variação entre turnos (10%)
CARGOS_CANDIDATO_UNICOPresidente, Governador, Senadorcargos verificados na busca por candidato único
MIN_ELEITORES_CANDIDATO_UNICO0ignora urnas com menos votantes que isso

Para reprocessar os CSVs (por exemplo, após baixar uma versão nova), apague a pasta cache/ antes de executar.

5Gerar o relatório HTML

Depois que o cache existe, gere a página estática. Os dados são embutidos no HTML; os gráficos usam Chart.js via CDN.

python3 gerar_relatorio.py

Abra docs/index.html no navegador para conferir. O limite de 10% do relatório fica na constante LIMIAR no início do script.

6Publicar no GitHub Pages

Os CSVs e o cache são grandes demais para o GitHub (limite de 100 MB por arquivo). Versione só o código e a pasta docs/; o .gitignore do projeto já exclui o resto.

git init
git add .gitignore analise_urnas.ipynb gerar_relatorio.py relatorio_template.html docs/
git commit -m "Relatório dos boletins de urna 2026"
git branch -M main
git remote add origin https://github.com/<usuario>/<repositorio>.git
git push -u origin main

No GitHub, abra Settings → Pages, em Build and deployment escolha Deploy from a branch, branch main, pasta /docs, e salve. Em um ou dois minutos o site fica em https://<usuario>.github.io/<repositorio>/.

Para atualizar: rode de novo os passos 4 e 5, faça commit de docs/ e git push.

7Observações sobre os dados

  • Uma linha do CSV = votos de um votável (candidato, legenda, branco ou nulo) em uma seção e cargo. Aptos e comparecimento repetem-se em todas as linhas da seção.
  • A chave de uma urna é SG_UF + CD_MUNICIPIO + NR_ZONA + NR_SECAO.
  • Seções agregadas aparecem sob a seção principal (coluna DS_SECOES_AGREGADAS).
  • No 2º turno só há Presidente e, em alguns estados, Governador.
